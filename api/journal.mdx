title: "Journal API — manage private journal entries"
sidebarTitle: "Journal"

---

The Journal API allows authenticated users to create, update, and delete private journal entries that are stored under their account and never shared with other participants. Each entry carries an `include_in_analysis` flag — when set to `true`, the entry's content is surfaced to the AI analysis pipeline as historical context, helping the trend model produce more personalized and accurate assessments over time.

---

## POST /api/journal

<span style={{display:"inline-block",background:"#16a34a",color:"#fff",borderRadius:"4px",padding:"2px 8px",fontWeight:700,fontSize:"0.8rem",marginBottom:"1rem"}}>POST</span> `/api/journal`

Creates a new journal entry for the authenticated user.

**Auth:** requires an active user session.

### Request body

<ParamField body="content" type="string" required>
  The text body of the journal entry. Must be a non-empty string after trimming whitespace.
</ParamField>

<ParamField body="includeInAnalysis" type="boolean">
  When `true`, this entry will be included in the historical context passed to `analyzeTranscript`. Defaults to `false`.
</ParamField>

### Response `200`

<ResponseField name="entry" type="object">
  The newly created `JournalEntry` row.
  <Expandable title="entry fields">
    <ResponseField name="entry.id" type="string">
      UUID of the journal entry, auto-generated by the database.
    </ResponseField>
    <ResponseField name="entry.user_id" type="string">
      UUID of the authenticated user who owns the entry.
    </ResponseField>
    <ResponseField name="entry.content" type="string">
      The trimmed text content as stored.
    </ResponseField>
    <ResponseField name="entry.include_in_analysis" type="boolean">
      Whether this entry is opted into the AI analysis context.
    </ResponseField>
    <ResponseField name="entry.created_at" type="string">
      ISO 8601 timestamp of when the entry was created.
    </ResponseField>
  </Expandable>
</ResponseField>

### Errors

| Status | Condition |
|---|---|
| `400` | `content` is missing, not a string, or empty after trimming |
| `401` | No authenticated user session |
| `500` | Database insertion failure |

## PATCH /api/journal

<span style={{display:"inline-block",background:"#f59e0b",color:"#fff",borderRadius:"4px",padding:"2px 8px",fontWeight:700,fontSize:"0.8rem",marginBottom:"1rem"}}>PATCH</span> `/api/journal`

Toggles the `include_in_analysis` flag on an existing journal entry. Only the entry owner can update their own entries; the query is scoped by both `id` and `user_id`.

**Auth:** requires an active user session.

### Request body

<ParamField body="entryId" type="string" required>
  UUID of the journal entry to update.
</ParamField>

<ParamField body="includeInAnalysis" type="boolean" required>
  The new value for the `include_in_analysis` flag.
</ParamField>

### Response `200`

```json
{ "success": true }
```

<ResponseField name="success" type="boolean">
  `true` when the entry was updated successfully.
</ResponseField>

### Errors

| Status | Condition |
|---|---|
| `400` | `entryId` is missing from the request body |
| `401` | No authenticated user session |
| `500` | Database update failure |

## DELETE /api/journal

<span style={{display:"inline-block",background:"#dc2626",color:"#fff",borderRadius:"4px",padding:"2px 8px",fontWeight:700,fontSize:"0.8rem",marginBottom:"1rem"}}>DELETE</span> `/api/journal?id=<entryId>`

Permanently deletes a journal entry. The deletion is scoped to the calling user — a user cannot delete another user's entries.

**Auth:** requires an active user session.

### Query parameters

<ParamField query="id" type="string" required>
  UUID of the journal entry to delete.
</ParamField>

### Response `200`

```json
{ "success": true }
```

<ResponseField name="success" type="boolean">
  `true` when the entry was deleted successfully.
</ResponseField>

### Errors

| Status | Condition |
|---|---|
| `400` | `id` query parameter is missing |
| `401` | No authenticated user session |
| `500` | Database deletion failure |

## Example

### Create a journal entry

```bash
curl -X POST https://your-sahara-app.vercel.app/api/journal \
  -H "Content-Type: application/json" \
  -H "Cookie: <SESSION_COOKIE>" \
  -d '{
    "content": "Had a difficult conversation today but felt heard by the group. Starting to feel a bit more hopeful.",
    "includeInAnalysis": true
  }'
```

```json
{
  "entry": {
    "id": "7f3e1c20-aaaa-4bbb-8ccc-ddddeeee0001",
    "user_id": "b9d1f4a2-1234-5678-9abc-def012345678",
    "content": "Had a difficult conversation today but felt heard by the group. Starting to feel a bit more hopeful.",
    "include_in_analysis": true,
    "created_at": "2025-01-15T14:05:22.000Z"
  }
}
```

### Toggle analysis inclusion

```bash
curl -X PATCH https://your-sahara-app.vercel.app/api/journal \
  -H "Content-Type: application/json" \
  -H "Cookie: <SESSION_COOKIE>" \
  -d '{
    "entryId": "7f3e1c20-aaaa-4bbb-8ccc-ddddeeee0001",
    "includeInAnalysis": false
  }'
```

### Delete an entry

```bash
curl -X DELETE \
  "https://your-sahara-app.vercel.app/api/journal?id=7f3e1c20-aaaa-4bbb-8ccc-ddddeeee0001" \
  -H "Cookie: <SESSION_COOKIE>"
```
